Installation
  1. Find a component

    Browse the library, where every component plays live, or list them all with npx designme list. Each has a page with its install name, props and code.

  2. Add it

    One command copies its files into your project. Add as many names as you like at once.

    $npx designme add agent-tree

    Each component lands in its own folder in ./designme, with its .html, .css and .js and a demo.html you can open straight away. The shared core is added once.

    $npx designme add agent-tree --react

    A typed .tsx component and its CSS in src/components/designme. Needs React 19, and works in Next.js, Vite and Astro islands.

    $npx designme add agent-tree --astro

    An .astro component with the same markup, CSS and script as the HTML version, in src/components/designme.

    $npx shadcn@latest add https://designme.dev/r/shadcn/agent-tree.json

    Every component is also a shadcn registry item, in React and in Astro (at /r/shadcn/astro/), for a project set up for shadcn/ui.

  3. Make it yours

    It is your code now, beside your own: change the markup, the words, the tokens and the demo data.

  4. Or hand it to your coding agent

    Every page has a Markdown copy, and llms.txt lists every component with its install command. A prompt to start from:

    Read https://designme.dev/llms.txt and pick the components for our screen.
For each one, read its .md page, then install it with:
  npx designme add <name> --react
Keep the installed files as they are and drive the components through their props from our state.

What every component comes with, whichever version you add.

  • You own the code

    The CLI copies the source into your project: HTML, CSS and JavaScript, a typed React component or an Astro component. Change anything.

  • Three styles, light and dark

    Blueprint, Soft and Clean, each with a light and a dark theme, picked with two attributes on <html>.

  • No clashes with your CSS

    Every CSS variable starts with --dm-, and in React every class and animation name with dm-, so they sit beside Tailwind, shadcn/ui or your own styles.

  • Your theme, if you want it

    Add the theme bridge with --theme-bridge and the components take the colours and corners of your shadcn/ui or Tailwind v4 theme.

  • Accessible

    ARIA roles and labels, live regions for what the agent is doing, keyboard support in most components, tap areas on touch screens and reduced motion.

  • Ready for AI coding tools

    Every component and docs page has a Markdown copy at its address plus .md, and llms.txt lists them all with their install commands.

More in the FAQ
Is it free?

Yes. Every component is free for personal and commercial work under the MIT licence. Fonts, icons, flags and brand marks from other projects keep their own licences, listed in NOTICE.md.

What do I need?

Node 18 or later to run the CLI. The React components need React 19 and work in Next.js, Vite and Astro islands. The HTML version needs only the shared core, which the CLI adds once.

Do I need Tailwind or shadcn/ui?

No. The components bring their own CSS. If your project uses shadcn/ui or Tailwind v4, the theme bridge (--theme-bridge) gives them your theme, and the shadcn CLI can add any of them.

Will their CSS clash with mine?

No. Every CSS variable starts with --dm-, and in React every class and animation name starts with dm- too, so nothing meets your own names.

What are Blueprint, Soft and Clean?

Three styles for the same components: Blueprint is technical and square with a lime accent, Soft is rounded with a blue accent, and Clean is black, white and grey with fully round controls. Each has a light and a dark theme. In your project, data-style on <html> picks one.

Can AI coding tools use it?

Yes. Every component and docs page has a Markdown copy at its address plus .md, and llms.txt lists every component with its install command. The Using with AI page in the docs has prompts to start from.
