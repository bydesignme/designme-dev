Automation canvas

A trigger, a few agent steps, and a run you can watch flow through. Free and MIT licensed, as HTML or a typed React component, in two styles with light and dark mode.

$npx designme add automation-canvas
Weekly design QAOn
Every Monday, 9:00
Drag the empty canvas or scroll to move around, and Control or Command with the scroll wheel, or a pinch, to zoom. With the canvas focused the arrow keys move the view, plus and minus zoom, and 0 or 1 fits it. Shift-click a step to add it to the selection, and Escape clears it.

01

Install

Add it to your project with the CLI.

HTML, CSS and JavaScript

$npx designme add automation-canvas

React

$npx designme add automation-canvas --react

The CLI copies the source into your project, so you own it and can change anything. The HTML version lands in ./designme with the shared core and a demo.html. The React version lands in src/components/designme and needs React 19; it works in Next.js, Vite and Astro.

02

About

What it is for and what it does.

Automation canvas draws an agent automation as cards joined by wires: a trigger, a few agent steps and where the result goes. People can add steps from a small + on the last step, or give the agent a model and tools from the connectors under it, pan and zoom round the canvas, select and drag the cards, click one to change its setting, and press Test run to watch the run light up each step and wire in turn.

  • When people set up recurring agent workflows, like a weekly design check that posts to Slack.
  • When a short flow is easier to understand as a picture than as a form.
  • When people build the flow themselves, a step at a time, from a short list of step types.
  • When each step has one main setting that people should be able to change in place.
  • When you want to show a test run moving through the steps before the automation goes live.
  • Each node has an icon, a colour, a title and a detail line, placed by x and y as fractions of the canvas, with y counted between the name over its top and Test run over its foot. edges wire nodes together by id.
  • With catalog, a step whose output leads nowhere yet gets a small + on its right (under it when the canvas stacks, or when there is no room to its right). A node's connectors add labelled + Model and + Tools buttons under it, with dashed stubs.
  • A + or a connector opens the step picker beside it: a search over a short list of step types in groups (after a step, the step groups, such as Tools, Logic and Actions; from a connector, its own group). Each type has an icon and a one-line description, shown at the foot of the picker for the type under the pointer or the arrows.
  • Picking a type calls onAddNode(type, from, via, group). Add a node with attach: { to: from, via } and its edge, and the canvas places it next to what it hangs from (to the right, or under it), clear of the other steps, their + buttons and their wires, and keeps that place in each layout. Models and tools are drawn as smaller steps on dashed wires. The wire to a new step draws itself in.
  • The + buttons go once the canvas holds maxNodes steps: 9, or 6 when the canvas stacks.
  • With balanced on (the default), nodes that share an x form a column and the columns spread evenly across the width.
  • Cards can be dragged; dragging a selected card moves every selected card. Dropping calls onNodeMove with each moved card's new centre. Below 560px wide the nodes stack down the canvas, using each node's narrow position if set; there a step with connectors sends its wire to a step on its left from its left side, so it passes clear of what hangs under it.
  • The canvas pans and zooms. Drag the empty canvas (one finger on a touch screen), scroll, or swipe a trackpad to pan; Ctrl or ⌘ with the wheel, or a pinch, zooms at the pointer, from 50% to 200%. The dots move with the cards, and panning stops before the cards' area leaves the middle of the canvas. The canvas never traps the page: the wheel and touch pan it only once someone has clicked or tapped in the component, or moved the keyboard focus into it. Until then the wheel and a finger scroll the page as usual, and a pinch does what the browser does. Ctrl or ⌘ with the wheel zooms the canvas at any time.
  • Small zoom buttons sit in the bottom right corner: zoom out, the zoom level (press it for 100%), zoom in, and fit, which centres every step and its + in view at 100% or less. New steps are placed clear of the buttons where there is room. view, defaultView and onViewChange hold where the canvas looks, as { panX, panY, zoom }. It starts with the whole canvas at 100%, and goes back to that when the canvas switches between wide and stacked.
  • Click a card to select it: its white card gets a light grey edge. Shift and a click adds a card to the selection or takes it out, Shift and a drag on the empty canvas draws a box that selects every card it touches, and a click on the empty canvas or Escape clears the selection. selection, defaultSelection and onSelectionChange hold it, as a list of ids.
  • The cursor is an open hand on the empty canvas, a closed hand while it pans, and a pointer on the cards.
  • Clicking a node selects it and opens a popover with its field, a menu of options. Picking one updates the node's detail and calls onValuesChange.
  • onRun adds a Test run button. Set each node's state to run or done and add wires to flowing as your run goes, and a soft light passes along each new wire.
  • The canvas is the whole component, edge to edge, with its dots all the way out. The automation's name and an optional green tag like "On" sit over its top left, and Test run with a status line that crossfades over its bottom left. The steps are laid out and fitted in the band between them, so neither covers a step at rest. The canvas fills the height it is given, or is 560px tall (640px when it stacks) when nothing gives it one.
  • Each node is a button with aria-expanded that shows whether its popover is open.
  • Each + is a button labelled with the step it adds after, like "Add a step after Post summary", and each connector is labelled like "Add a tool to Agent: audit". Both have aria-haspopup="dialog" and aria-expanded.
  • The picker is a dialog labelled the same way. Its search is a combobox that controls a listbox of options in labelled groups, and points at the current option with aria-activedescendant; each option is described by its one-line description.
  • Opening the picker puts the focus in its search. The up and down arrows move through the options and wrap, typing filters them, Enter adds the current one and moves the focus to the new step, and Escape closes the picker and gives the focus back to its +.
  • An aria-live="polite" region says which step was added and where.
  • The popover has role="dialog", labelled with the node's title, and is inert while closed.
  • Enter or Space on a node opens its popover with the focus in it, and Escape or Done closes it and gives the focus back to the node.
  • Setting options use role="menuitemradio" with aria-checked, and the dropdown is a menu button with aria-expanded: the arrows open it and move through the options and wrap, Home and End jump, Enter or Space picks, and Escape closes it back to the button.
  • The canvas is a focusable group with aria-roledescription="canvas", labelled by label ("Automation canvas" by default) and described by a hidden line that lists its controls. While the canvas has the focus, the arrow keys pan it (with Shift, in bigger steps). While the canvas, a card or a zoom button has the focus, plus and minus zoom, 0 or 1 fits, and Escape clears the selection.
  • Its focus ring is the quiet grey, shown only from the keyboard: a click gives the canvas the focus without a ring. Tab goes from the canvas through the cards and their + buttons, and a card that takes the focus out of view glides into view.
  • The zoom buttons are a toolbar labelled "Zoom". The level reads like "Zoom 125%, reset to 100%", and zoom out and zoom in turn aria-disabled at 50% and 200%.
  • The aria-live region also says the zoom level after the buttons and keys, and how many steps are selected after a Shift click, a box or a clear.
  • The wires are aria-hidden. With reduced motion on, the light along a wire and a new wire's draw are skipped, and the view jumps to where the buttons and keys send it instead of gliding.

/* ---------- Automation canvas: add steps, drag them, change their settings, and test run the flow ---------- */
export default function AutomationCanvasDemo() {
  const [nodes, setNodes] = useState(NODES);
  const [edges, setEdges] = useState(EDGES);
  const [states, setStates] = useState<Record<string, AutomationNode['state']>>({});
  const [flowing, setFlowing] = useState<AutomationEdge[]>([]);
  const [status, setStatus] = useState('Every Monday, 9:00');
  // picking a new schedule rewrites the line in the corner
  const [trigger, setTrigger] = useState('Mondays 9:00');
  const seq = useRef(0), runId = useRef(0), now = useRef({ nodes, edges });
  now.current = { nodes, edges };
  const wait = useWait();

  // Test run lights each step in turn; a soft light passes along each wire the run reaches, and the wire stays lit. The
  // agent's model and tools light with it, and the steps added after the last one run in turn
  const run = async () => {
    const id = ++runId.current, w = async (ms: number) => { await wait(ms); if (id !== runId.current) throw 'stop'; };
    const mark = (k: string, s: AutomationNode['state']) => setStates(x => ({ ...x, [k]: s }));
    const { edges: E } = now.current, subs = E.filter(e => e[0] === 'b' && e[2]);
    try {
      setStates({}); setFlowing([]); setStatus('Running test');
      await w(220); mark('t', 'run'); await w(600); mark('t', 'done');
      setFlowing([['t', 'a'], ['t', 'b']]); await w(620);
      mark('a', 'run'); mark('b', 'run'); subs.forEach(e => mark(e[1], 'run')); setFlowing(f => [...f, ...subs]); await w(1100);
      mark('a', 'done'); subs.forEach(e => mark(e[1], 'done')); await w(400); mark('b', 'done');
      setFlowing(f => [...f, ['a', 'c'], ['b', 'c']]); await w(620);
      mark('c', 'run'); await w(700); mark('c', 'done');
      let at = 'c', s = 3.4, nx: AutomationEdge | undefined;
      while ((nx = E.find(e => e[0] === at && !e[2]))) { const e = nx; setFlowing(f => [...f, e]); await w(620); mark(e[1], 'run'); await w(700); mark(e[1], 'done'); at = e[1]; s += 1.3; }
      setStatus(`Test passed in ${s.toFixed(1)}s`);
    } catch (e) { if (e !== 'stop') throw e; }
  };

  // the preview's story: one test run, then the person adds a step after the last one from its +, zooms in a step and fits
  // the whole automation back in view
  const ref = useRef<HTMLDivElement>(null);
  useStory(ref, async ({ wait: sw, press }) => {
    await sw(1600); press('.dm-acx-run');
    await sw(6200); press('.dm-acx-h');
    await sw(1500); press('.dm-acx-o[data-id="ticket"]');
    await sw(1500); press('.dm-acx-zi');
    await sw(1000); press('.dm-acx-fit');
  });

  return (
    <div ref={ref} style={{ width: '100%' }}>
      <AutomationCanvas name="Weekly design QA" tag="On" status={status}
        nodes={nodes.map(n => ({ ...n, state: states[n.id] }))} edges={edges} flowing={flowing} catalog={CATALOG}
        onAddNode={(type, from, via, group) => {
          const id = 'n' + ++seq.current;
          setNodes(ns => [...ns, { id, icon: type.icon, color: group.color, title: type.title, detail: type.detail, field: type.field, attach: { to: from, via } }]);
          setEdges(es => [...es, via === 'out' ? [from, id] : [from, id, via]]);
        }}
        onValuesChange={v => { if (v.t !== trigger) { setTrigger(v.t); setStatus(v.t.replace('Mondays', 'Every Monday,')); } }}
        onRun={run} />
    </div>
  );
}

  y: number;

  panY: number;

type Box = { l: number; t: number; r: number; b: number; w: number; h: number };
type Anchor = { x: number; y: number; d: 'r' | 'l' | 'd' };
type Bez = [number, number][];

// a wire from a step's output (or a connector's foot) into the side of the next step that faces it
function link(a: Anchor, B: Box): Bez {
  let p: [number, number], e: 'l' | 'r' | 't' | 'b';
  if (a.d === 'l') { if (B.t >= a.y + 8) { p = [B.l + B.w / 2, B.t]; e = 't'; } else if (B.r <= a.x - 8) { p = [B.r, B.t + B.h / 2]; e = 'r'; } else { p = [B.l + B.w / 2, B.b]; e = 'b'; } }
  else if (a.d === 'r') { if (B.l >= a.x + 8) { p = [B.l, B.t + B.h / 2]; e = 'l'; } else if (B.t >= a.y) { p = [B.l + B.w / 2, B.t]; e = 't'; } else { p = [B.l + B.w / 2, B.b]; e = 'b'; } }
  else { if (B.t >= a.y + 8) { p = [B.l + B.w / 2, B.t]; e = 't'; } else if (B.l >= a.x) { p = [B.l, B.t + B.h / 2]; e = 'l'; } else { p = [B.r, B.t + B.h / 2]; e = 'r'; } }
  const dx = p[0] - a.x, dy = p[1] - a.y, k0 = Math.max(24, Math.abs(a.d === 'd' ? dy : dx) / 2), k1 = Math.max(24, Math.abs(e === 'l' || e === 'r' ? dx : dy) / 2);
  const c1: [number, number] = a.d === 'r' ? [a.x + k0, a.y] : a.d === 'l' ? [a.x - k0, a.y] : [a.x, a.y + k0];
  const c2: [number, number] = { l: [p[0] - k1, p[1]], r: [p[0] + k1, p[1]], t: [p[0], p[1] - k1], b: [p[0], p[1] + k1] }[e] as [number, number];
  return [[a.x, a.y], c1, c2, p];
}
const bez = (q: Bez, t: number): [number, number] => { const u = 1 - t; return [0, 1].map(i => u * u * u * q[0][i] + 3 * u * u * t * q[1][i] + 3 * u * t * t * q[2][i] + t * t * t * q[3][i]) as [number, number]; };
const dOf = (q: Bez) => `M${q[0].join(' ')} C${q[1].join(' ')} ${q[2].join(' ')} ${q[3].join(' ')}`;

/* where a new step goes: as near as it can to just after what it hangs from (to the right of a step, under a connector, or
   under a step when the canvas stacks), clear of every step, + and connector, keeping off the wires already drawn, with its
   own wire crossing no step, and with room for its own + inside the canvas */
function spot(W: number, H: number, w: number, h: number, a: Anchor, hasOut: boolean, narrow: boolean, others: Box[], knobs: Box[], wires: Bez[]): AutomationPoint {
  const M = 8, obst = [...others, ...knobs];
  const samples = wires.flatMap(q => Array.from({ length: 15 }, (_, i) => bez(q, (i + 1) / 16)));
  const want = a.d === 'r' ? [a.x + 56 + w / 2, a.y] : [a.x, a.y + 40 + h / 2];
  const inside = (p: [number, number], b: Box, m: number) => p[0] > b.l - m && p[0] < b.r + m && p[1] > b.t - m && p[1] < b.b + m;
  const ov = (A: Box, B: Box, m: number) => Math.max(0, Math.min(A.r, B.r + m) - Math.max(A.l, B.l - m)) * Math.max(0, Math.min(A.b, B.b + m) - Math.max(A.t, B.t - m));
  let best: Box | null = null, bs = Infinity, soft: Box | null = null, ss = Infinity;
  // room to spare first; on a crowded canvas, just clear of the rest
  for (const G of [14, 4]) {
    if (best) break;
    for (let y = M; y + h <= H - M; y += 8) for (let x = M; x + w <= W - M; x += 8) {
      const B = mk(x, y, w, h);
      if (hasOut && (narrow ? B.b + 34 > H - 4 : B.r + 34 > W - 4)) continue;
      let sc = Math.hypot(x + w / 2 - want[0], y + h / 2 - want[1]);
      if (a.d === 'r' ? B.l < a.x + 24 : B.t < a.y + 24) sc += 250;
      sc += samples.filter(p => inside(p, B, 6)).length * 60;
      const q = link(a, B); for (let i = 1; i < 12; i++) { const p = bez(q, i / 12); if (others.some(o => inside(p, o, 4))) sc += 30; }
      const hit = obst.reduce((s, o) => s + ov(B, o, G), 0);
      if (!hit) { if (sc < bs) { bs = sc; best = B; } }
      else if (hit * 10 + sc < ss) { ss = hit * 10 + sc; soft = B; }
    }
  }
  const B = best ?? soft ?? mk(M, M, w, h);
  return { x: (B.l + w / 2) / W, y: (B.t + h / 2) / H };
}

Questions

What people ask about it.

Does Test run execute the automation?
No. It calls onRun. Your code runs the steps and updates each node's state and the flowing list, which the canvas animates.
Can people move around a bigger automation?
Yes. They pan by dragging the empty canvas, and with one finger or by scrolling once they have clicked or tapped into it, zoom with Ctrl or ⌘ and the wheel, a pinch or the corner buttons, and fit brings every step back into view. Hold view with onViewChange to start somewhere else, or to keep the view between visits.
How do I let people add steps?
Pass a catalog with the step types to offer, and handle onAddNode: add a node with attach: { to: from, via }, without x or y, and an edge from from to it (with via as its third value for a model or a tool). The canvas finds the new step a place.
How do I lay it out for small screens?
Give nodes a narrow position. Below 560px the canvas uses those positions, keeps every card inside the canvas, and wires top to bottom. Without them, nodes stack in a column down the middle.
How do I save where people dragged the cards?
Handle onNodeMove(id, at, narrow). It reports the card's centre as fractions of the canvas and whether the narrow layout was in use, so you can store each layout separately.
How do I reset the wires before a new run?
Clear the flowing array when the run starts. Wires stay lit for as long as they are listed in it.
