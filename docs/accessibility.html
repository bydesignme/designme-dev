Accessibility

What the components do for people using a keyboard, a screen reader or reduced motion, and where they still fall short.

Roles and labels

Components use the ARIA pattern that fits what they do. For example:

PatternRoles and statesFor example
MenusA menu of menuitem rows. The button that opens one reports aria-expandedButtons
Lists you pick fromA listbox of option rows. The search box that drives one is a comboboxCommand palette, Country select
A single choiceA radiogroupDecision prompt
On or off settingsA switch with aria-checkedAgent settings
Tabstablist, tab and aria-selectedCode viewer, Thread panel, Segmented control
Slidersaria-valuenow and aria-valuetextDesign tuner
File treesA tree of treeitem rowsFile explorer
PopoversA labelled dialog, like the calendarDate picker, Citation hover card
Toggle and icon buttonsToggles report their state with aria-pressed. Icon-only buttons have a labelButtons, Line chart

Live updates

Agent work changes while you watch. The parts that change are aria-live="polite" regions, so the change is read out: Status pill, the thread above Composer, the message line of Context meter, the thread in Comments and the month in Date picker.

Decorative motion, like status glyphs and the wires of a canvas, is aria-hidden, so screen readers hear the words, not the animation.

Focus shows as a 2px ring in the accent's mark colour, using :focus-visible.

Most components work fully with a keyboard. A few, like Kanban board and File explorer, are still getting their keyboard support.

Reduced motion

When the device asks for less motion (prefers-reduced-motion: reduce), the components cut it in two places:

In the CSS

The shared CSS cuts every CSS animation and transition inside the components to almost nothing.

In the scripts

The HTML version reads REDUCE, which the core sets from the same setting. React components that animate from script use the useReducedMotion() hook from lib/hooks.ts.

Count-ups finish at once, rows move without gliding, and the content still changes.

Contrast

Text and marks

The accent has separate roles for fills, text and marks. Text in the accent aims for 4.5:1 and marks for 3:1, on the surface and on the grey chips and tinted rows they sit on. See Theming.

A light accent

Blueprint's lime is too light for text on white, so in light mode accent text uses the ink colour and marks a darker lime.

Edges

An off switch and an empty box are drawn in a grey that holds 3:1 against the surface. An accent fill keeps a thin edge in the mark colour, so a light accent still has an outline.

For each component

Every component's page lists what it does under About, then Accessibility. Its Markdown copy has the same list. These notes describe what the code does. Check your product with your own content and assistive technology too.
